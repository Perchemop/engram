# Contributors

Engram is built by the people who take the time to improve it. This file
recognises meaningful contributions of every kind, not only code.

Names are added here as contributions land — when a pull request is merged,
an issue is triaged, a translation is reviewed, or research is written up and
used. If you have contributed and are not listed, that is an oversight, not a
judgement: open an issue and it will be fixed.

## Founding author

Engram was founded and is maintained by its original author, who defined the
product, the architecture and the process the project runs on. They are
reachable through the repository's GitHub account,
[@Perchemop](https://github.com/Perchemop), and hold the maintainer role
described in `GOVERNANCE.md`.

## Contribution kinds recognised here

- **Code** — domain logic, UI, persistence, import/export.
- **Tests** — unit and integration tests, and the cases that catch real
  bugs.
- **Documentation** — README, guides, architecture notes, known limitations,
  accessibility and security documents.
- **Design and accessibility** — visual identity, contrast work, keyboard and
  screen-reader reviews.
- **Triage** — reproducing bugs, labelling, and closing duplicates with a
  clear explanation.
- **Research** — original summaries of public algorithms and conventions,
  with sources, written up in `docs/research/`.
- **Translations** — once localisation exists.

## Project identity (agent builds)

Engram is built largely by AI build agents working under the maintainer's
direction (see `GOVERNANCE.md`). Their commits are authored under the
project's single bot identity, so that human authorship is never misattributed:

- **Engram Dev `<dev@example.com>`** — the project's build identity, used for
  all agent-authored commits, documentation and tree changes.

This identity is the project's, not a person's. It is listed here so that the
contribution record is honest about how the work was produced.
